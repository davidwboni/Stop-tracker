# Check Pay entry — proposed, awaiting approval

One screen only. Purpose: help a driver choose a free manual comparison or an AI extraction path when external paperwork arrives. It shows the selected FULL pay period, same-basis expected contractor payout from Money, and a lifecycle status. It must never compare own business expenses directly with contractor payout. Gross stop earnings are supporting detail, never a substituted final payout.

Mockup state: closed period 17 Aug–13 Sep 2026; Awaiting statement; estimated expected contractor payout £4,264.12 (before my own business expenses/tax). Small explanation links to Money calculation. Screen question “How would you like to check your statement?” Manual card FIRST, “Enter totals manually · Free,” one clear action “Enter statement totals.” Optional explanation that the source can be a provider invoice or contractor spreadsheet. Second card “Upload with AI,” shows exact remaining statement trial count if server status is known; after the first 3 successful checks, Pro. Action “Choose a file” after entitlement check, not an immediate checkout upsell. Accepted eventual inputs PDF, JPEG/PNG/WebP, screenshots, CSV/XLSX subject to validated parsing; HEIC needs explicit conversion handling or unsupported-type guidance. Each upload path -> extract/parse -> review/edit -> compare -> confirm, with confidence in Review and no silent saved check. Manual remains available on failure. AI only maps fields; all arithmetic is deterministic.

Actions: period picker carries Home/Money selection. Manual opens an editable statement comparison draft for that period. AI file chooser shows preparation state then the next Review screen, not a final difference. Back from an unsaved draft/selected file asks before discarding. Current checked period replaces initial CTA with “Review saved check”; Needs recheck retains previous results as stale. Reconciled is explicit resolution, never automatic equality. Guests see features but must use permanent account before purchasing Pro; manual free is accessible for guest local records.

First-time/empty: no work this period -> prompt Log work; don't invent expected payout. In-progress period -> “Tracking” and date range, with clear possibility to add a statement if driver has one. Loading -> stable skeleton for totals and trial state; no 0 or optimistic 3 trials. Missing fee or expense data -> payout unavailable, explanation/link to relevant records. Offline: cached records clearly labelled; manual draft may be entered locally only if persistence is implemented/verified; AI picker disabled with retry. Errors keep the chosen file/draft until a user chooses to discard, except requests are never silently retried at additional cost.

Mobile/desktop: fixed five-item nav Check Pay selected, safe-area, file picker camera/gallery on supported devices, keyboard-safe draft, minimum ~44px controls; max-width 860 desktop with two aligned action cards. Transitions 150–250ms purposefully mark selected path and extraction stages; reduced motion immediate. No upload scanning spinner with indeterminate promises: show named stages and timeout/error recovery.

Analytics: check_pay_opened, statement_manual_started, statement_ai_started, statement_reviewed, statement_compared, discrepancy_found; stage-abandon events only with consent. No statement content, names, amounts, address, contractor name, source filename, receipt values or provider response. Core Check Pay entry triggers no AI or billing API on view except server-side usage/entitlement status query when required.

Privacy: keep original statement file only in transient memory/request for processing, do not permanently upload it into Firebase Storage unless a later document archive is separately approved; store reviewed structured values with provenance and verification state in owner-scoped records. DeepSeek processes data submitted to it; disclose this accurately. Paid AI and route credentials server-only. Consistent currency, period, tax basis and contractor charges are confirmed by user before a comparable discrepancy is saved. Claim no encryption beyond what is actually verified.

Missing before implementation: specify accepted spreadsheet parser and guard against formulas/macros, amount scope and gross-vs-net field mappings, caps and page-count limits, server atomic free-use count, signed-in entitlement and downstream Review/Compare screens. This is a proposal only; do not implement Check Pay entry until approval.
