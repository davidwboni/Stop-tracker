# Add Expense — approved implementation

Manual defaults: Other category, today's local date, My expense (Contractor charge when opened from that list filter). Amount required; date valid; positive GBP, two decimal places. Description/notes/receipt optional. Sources stay separate; percentage fees never entered here. Existing records retain their id and reconciliation is invalidated by useExpenses on save. A saved expense is not payment confirmation.

Mobile: full-height focus-trapped dialog; visualViewport tracks keyboard; safe-area footer; 16px+ fields; 44px+ controls; native Android back dismisses keyboard first, then requests discard confirmation. Desktop: 480px dialog. Reduced-motion supported; 200ms entry. Light/dark shared tokens. Close/escape/back and browser unload protect unsaved drafts. Signed-in offline saves are blocked with draft retained; guest saves local. No automatic draft persistence of receipt content.

Receipt: JPEG/PNG/WebP/PDF up to 8 MB; manual attachment does not invoke AI. New attachments default to NOT retained. Explicit checkbox stores a file in owner-scoped Storage (account) or IndexedDB (guest). Metadata retains only path, MIME, local flag, not public download tokens or original filenames. Receipt can be viewed/downloaded from expense details. Replacement/delete cleanup uses a retrying Firestore trigger; failed uploads get immediate best-effort cleanup and a server orphan queue after 7 days. Guest storage is local and can be cleared by the browser; it is not an account backup. Photo metadata is not stripped: warn/support redaction in future privacy policy; only knowingly selected files are retained/sent.

AI: server checks permanent authentication and authoritative entitlement; no receipt free trial. Upload -> extract -> editable review -> explicit checked-details checkbox -> save. Missing/invalid/foreign-currency amounts remain blank; no implicit conversion. Source is chosen by the user; AI cannot infer it. Files are request payloads, not staged in Storage. DeepSeek provider retention is separate from Stop Tracker file retention and must be disclosed accurately. No provider retention promises. No raw prompts/responses or receipt values logged. Outputs are allowlisted and limited; no AI arithmetic. Up to 4 PDF pages; rejects longer PDFs rather than silently truncating. Per-user server request cap 20/day and concurrent request lock; failed paid attempts count towards cap. Structured usage only, no document contents. No document extraction cache.

Deployment gates: new functions getReceiptStatus, extractExpenseReceipt, cleanupExpenseReceipt, queueReceiptCleanup, removeOrphanReceipts plus Storage rules must be deployed. DEEPSEEK_API_KEY stays a Firebase secret. RECEIPT_AI_ENABLED defaults false; set true only after staging confirms current provider model deepseek-flash image support with representative synthetic receipts and all pages. Public docs returned conflicting cached versions during implementation; no live paid-provider test was performed. Cloud Storage CORS must allow authorized app origins for authenticated getBlob downloads. Scheduler/Storage trigger service permissions and bucket must be verified. Live provider, entitlement, Storage rules/emulator, iOS/Android and browser visual QA remain release gates; component tests are not evidence of those checks.

Analytics: explicit events only with analytics consent: expense_ai_started/completed/failed/saved, expense_manual_saved, expense_save_failed, expense_dismissed. Only source/mode enums; no values or file data. PostHog initialization remains a separate existing integration gate.
