# Money Overview — approved 27 September 2026

Implemented on feat/approved-home. Replaces the temporary MoneyHomeBridge route. One scrollable mobile screen: Money header, hide-money/profile, period selector, Overview/Expenses/Insights, recorded financial waterfall, estimated take-home, collapsed calculation, and like-for-like contractor payout comparison. Desktop uses two columns. Reuses existing five-item app navigation. Safe-area/nav spacing comes from shared shell; 44px+ actions, native 16px period select, keyboard-operable details, reduced motion, light/dark tokens.

Totals use stored daily gross earnings and historical contractor fee snapshots. Each daily fee is rounded to pennies before summing (existing Home convention). Contractor charges and own expenses remain separate. Expected payout = gross minus fees minus contractor charges. Take-home additionally subtracts own expenses, before personal tax. Fee omissions in legacy records block net totals; current settings never silently reprice history. Recurring expectations stay outside recorded totals with a link to Expenses.

Comparison contract: payoutComparison {scope:'contractor_payout', currency:'GBP', taxBasis:'same_as_records', basisConfirmed:true, start, end, statementPence, expectedPence, revision}. Revision is SHA-256 over the selected range and source records; it detects changed records, not a security signature. Legacy gross comparisons are not relabelled as payouts. Missing basis/range data -> Complete comparison. Changed revision or needsReview -> Needs recheck. Matching figures -> Checked, never automatic reconciliation. Reconciled display additionally requires explicit resolvedAt; resolution workflow remains part of the forthcoming Check Pay design.

Integration: Money opens existing Check Pay in a narrowly scoped manual payout mode with fixed selected period. User confirms GBP, identical dates, after-contractor/before-own-cost scope and the same tax/VAT treatment. AI's existing gross extraction does not populate this payout input. No upload or AI is called in payout mode. A successful save records Checked, not Reconciled. Save failures retain the form; signed-in offline writes are refused. Context persistence now completes before local success is shown and updates only the selected period map entry. No automatic statement tax conversion or inferred mappings.

States: load placeholders, no transient zero totals; independently available gross/expense rows remain visible on partial failure but net/comparison are blocked. Work retry calls forceSync; expense retry reconnects its listener. Cached/offline records are labelled without inventing a freshness timestamp (current data layer supplies none). No work -> Log work; missing pay anchor -> Set pay period. A Home-selected week is preserved but comparison requires a full pay period. Period range only is passed through browser navigation state, never copied financial arrays.

Analytics: consent-gated money_overview_viewed, money_period_changed, money_breakdown_opened, money_comparison_opened with source enum only. Removed Home's duplicate money view emission. No rates, dates, amounts, receipt data or replay.

Validation: calculation and comparison model tests, Money state/masking tests, Money-to-Check-Pay confirmation/save/failure integration tests plus prior approved-screen regression tests; production build. Actual iOS/Android rendering, Firebase integration/rules and production browser validation remain release gates. No deployment or Pro billing changes in this work.
