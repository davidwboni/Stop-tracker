# Review Extracted Data — proposed, awaiting approval

One screen. User checks an AI draft before any comparison or permanent saving. All example content is illustrative.

Purpose: “Did we read your statement correctly?” Not a discrepancy result, not proof of payment. No take-home headline, charts, upsell, provider-specific fields or automatic saving. Entered manual figures can use this same normalized review model later.

Hierarchy: back to Check Pay; title Review statement; compact Upload / Review / Compare indicator. Then actionable amber “1 item needs attention” linking/focusing the first uncertain field. Matching pay-period range and GBP currency. Editable final contractor payout emphasized with “From statement · Unverified” label, no green success styling. Earnings section and contractor costs sections have collapsible line items; every item has a source label/page locator when extraction supplies a verified locator. Counts optional, no invented zeros. Missing values say Not found. One primary Continue to comparison button in safe-area sticky footer. Secondary View source opens a transient document preview; original file must remain in memory until draft discarded or completed, then release object URLs. Corrections never rerun AI.

Illustrative mockup: 17 Aug–13 Sep 2026, GBP; final contractor payout £4,217.69; collapsed Work earnings £5,499.55; contractor/admin fee £329.97; expanded Contractor charges £951.89 showing Lease £525.00 flagged “Check amount” and “Other charges £426.89”. These reconcile arithmetically: £5,499.55 − £329.97 − £951.89 = £4,217.69. Flag reflects uncertain extraction, not a detected difference from expected records. No expected-value difference appears until Compare.

Interaction: tapping warning focuses flagged field; tap any amount to edit with decimal keyboard; explicit mark-reviewed for flagged values. Button becomes available when required period, currency, final payout and unresolved critical warnings are handled. Unknown optional counts do not block a payout-only comparison. Unknown mandatory payout does block. If itemized totals and printed final total disagree, deterministic code warns; never overwrite either. Tax basis must be explicit (VAT included/excluded/unknown); incompatible/unknown basis blocks comparable payout until resolved. Changing period returns a focused period decision, never rewrites pay setup. Discard asks only when a draft exists. Back restores the same draft without another AI charge.

First user: brief “Tap any value to correct it.” Returning: same concise layout, no walkthrough. Empty extraction offers manual entry or choose another file and explains trial outcome. Loading shows named preparation/reading stages and bounded timeout, not invented progress percentages. Failures preserve file/draft where technically possible and no automatic paid retries. Offline corrections work in memory; signed-in save waits for connection, clearly labelled. Reload draft recovery requires separately consented temporary persistence; default no financial content in sessionStorage/localStorage for signed-in draft.

150–250ms disclosure/focus transitions; reduced-motion immediate, aria-live extraction/error summary, explicit labels and statuses rather than color alone; focus moves to first invalid field; 44px+ targets and 16px input fonts. iOS Safari uses safe-area footer and dynamic viewport/keyboard adjustments. Android Chrome/native handles Back with dirty-draft guard, picker cancellation leaves draft intact. PWA shares web behavior. Desktop max-width ~1100 with optional source preview beside editable values; mobile source preview accessible by button, not an illegible split screen.

Analytics: statement_review_opened, statement_field_corrected (no field contents; at most allowlisted field group), statement_reviewed, statement_review_validation_failed, statement_draft_abandoned; consent required. Timing bucket optional, no financial amount/source text/filename/contractor/profile info/replay. Save only confirmed structured statement, period, currency, tax basis, source method, per-field review state and minimal mappings. Do not automatically create expense records from extracted contractor charges; match existing entries and separately confirm additions to prevent double counting. No recurring rules without confirmation. Deterministic code handles totals and comparisons. Source documents only transient; disclose external AI processing accurately.

Implementation decisions before release: reliable per-field uncertainty and source locators, standard earnings/deductions/charges schema, VAT treatment, duplicate charge matching and confirmed-save contract. Do not fabricate model certainty percentages. Spreadsheet/CSV mapping is a separate input adapter with formula/macro execution forbidden and bounded rows/bytes. This review is a proposal; do not implement before approval.
